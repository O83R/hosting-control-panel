# مرجع VPS الحالي — حقائق مؤكدة وليست أسراراً

آخر أدلة المستخدم: 17 نوفمبر 2026 (PROD-SAFETY-01 .. 07A). المرجع هو **معلومات التصميم والتشغيل فقط**. لا ننسخ هوية المضيف أو العناوين العامة أو ملفات البيانات.

## مواصفات وأحمال تمت معاينتها
| البند | المثبت بالدليل |
|---|---|
| CPU | أربع vCPU (AMD EPYC) |
| RAM | نحو 7.8 GiB |
| Swap | ملف Swap بحجم 4 GiB؛ كان الاستخدام نحو 3.6–3.9 GiB |
| التخزين | قسم رئيسي ext4 بحجم 96 GiB، مستخدم منه نحو 59% عند الفحص |
| cgroup | cgroup v2، ومتحكمات cpu/memory/io/pids متاحة |
| Docker | محرك root أساسي وخمسة محركات Rootless تم الوصول إليها (waterf, alhafdat, abduh, inst, paneldev) |
| Rootless | Cgroup driver=systemd وCgroup version=2، وLinger=yes للمستخدمين الخمسة |
| Containers | 21 حاوية جارية قبل إيقاف محرك inst؛ 0 حاوية على inst |
| الضغط | قياسات PSI للذاكرة صفر أثناء الفحوص اللحظية؛ عداد oom_kill في المضيف 0 |
| إيقاف inst | 06B PASS: Docker service inactive، وعملياته اختفت؛ RAM المتاحة ارتفعت ~1.5→2.4 GiB؛ Swap المستخدمة انخفضت ~3.9→3.1 GiB |
| الاستعادة | تم تشغيل خدمات النسخ بنجاح بحسب systemd؛ **لم يثبت اختبار استعادة شامل** |

**مهم:** لم يتم في المحادثة إثبات إصدار نظام تشغيل VPS القديم أو جميع إعدادات SSH والجدار الناري أو قواعد التخزين أو اسم مزود VPS. لذا لا ينبغي ادعاء وجود تطابق حرفي.

## نموذج الخدمات على الخادم الأصلي
- Root Docker: Nginx Proxy Manager، Uptime Kuma، Portainer، موقع قديم للمعهد PHP/Dashboard/MariaDB.
- مشروع مصانع المياه: API + Next.js Admin + PostgreSQL؛ بالإضافة إلى حاويتَي Restore منفصلتين غير إنتاجيتين.
- مشروع مركز الحافظات: Frontend + Backend + Redis + PostgreSQL.
- مشروع أحكام: Nginx + Scheduler + App + Redis + قاعدة بيانات.
- لوحة استضافة تجريبية: حاوية Developer Panel.
- مستخدم المعهد (inst): تم إيقاف محركه مؤقتاً لعدم وجود حاويات ونظراً لأن المشروع لم ينشر بعد؛ خدمة docker.service كانت enabled (قد تبدأ عند إقلاع المضيف).

## عزل الشبكة والمراقبة
- Uptime Kuma كان بحالة healthy، ومربوطاً بمضيف محلي: `127.0.0.1:3001 -> container:3001`.
- شبكته `monitoring_net`؛ يتصل Nginx Proxy Manager بشبكتي `monitoring_net` و`proxy_net`.
- Kuma يستخدم bind mount إلى `/app/data`؛ لا تنسخ هذا التخزين إلى الخادم الجديد.
- توجد لوحة استضافة محلية أمكن الوصول لها سابقاً عبر نفق SSH؛ **لم يتم التحقق من إعداداتها الكاملة**.
- لا توجد خدمة Prometheus/Grafana/node_exporter معروفة من فحص الأسماء المحدد؛ ليس دليلاً على غياب كل آلية مراقبة.

## مشكلات ثبتت وينبغي ألا نكررها في التصميم الجديد
- 162 عملية zombie داخل لوحة إدارة مصانع المياه (108 chromium و54 crashpad)، مملوكة لـ next-server؛ السبب البرمجي الكامل لم يثبت. لا تعالج بحذف عمليات أو إعادة تشغيل عشوائية؛ راجع lifecycle الخاص بالمتصفح وصحة فحوص التطبيق.
- معظم الحاويات القديمة لا تمتلك حدود ذاكرة/PIDs صريحة؛ لا تعتمد حدوداً جديدة قبل القياس والاختبار.
- محركات rootless قد تستهلك RAM ملحوظة حتى لو لم تكن عليها حاويات، كما حصل مع inst.
- Swap المرتفعة وحدها لم تكن دليلاً على thrashing: vmstat أظهر si/so=0 خلال الفترة المقاسة.
- مخرجات `docker stats` لا تشمل كامل ذاكرة عمليات dockerd/rootlesskit؛ احتفظ بمحاسبة مضيف منفصلة.

## النسخ الاحتياطي
أظهرت خدمات `vps-infrastructure-backup.service` و`wf-water-factories-backup.service` حالة `Result=success` و`ExecMainStatus=0`. كما ظهرت خدمات تدقيق/عقد/تجهيز النسخ للوحة الاستضافة بنجاح. الخدمات المجدولة لم تُختبر استعادتها بالكامل في هذه المحادثة. عند إنشاء VPS جديد، أعد تصميم نسخ مستقلة لمشاريعه، ومخزن خارج الخادم، وتشفير، واستعادة تجريبية، وتحقق من زمن وفقد التعافي RTO/RPO.

## ما ننقله وما لا ننقله
**ننقل كتصميم:** Ubuntu LTS، cgroup v2، Docker Compose، Rootless لكل مستخدم مطلوب، Proxy، NPM، Kuma، منافذ إدارة loopback، شبكات Docker، مراقبة موارد، نسخ احتياطي مُختبَر، توثيق قبول وتراجع.

**لا ننقل:** ملفات /srv/apps، قواعد البيانات، الصور الخاصة، /home/*/.local/share/docker، أسرار .env، هويات SSH، شهادات TLS، كلمات المرور، مفاتيح التشفير، بيانات Kuma/NPM، الحسابات والأدوار القديمة أو إعدادات DNS.

## فرق مقصود
النسخة الجديدة تبدأ بعدد قليل من مستخدمي Rootless؛ لا نستنسخ خمسة محركات افتراضياً حتى لا نكرر استهلاك الذاكرة. لا تنشأ حاويات استعادة دائمة دون حاجة، ولا تفتح واجهات الإدارة على الإنترنت، ويعتمد Ubuntu Server 24.04 LTS الجديد بعد التحقق من دعم Docker له.
